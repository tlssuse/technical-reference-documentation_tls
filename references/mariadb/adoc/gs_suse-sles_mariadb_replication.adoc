== Introduction

This guide provides step-by-step instructions for setting up a primary-replica topology for {mariadb-long} on {sles-long}.
The configuration relies on maintaining copies of a database across multiple hosts, replicating data from an identified primary to one or more secondaries.
Distributing the data and workloads, organizations can deliver improved performance, maintain data consistency, and support high availability and disaster recovery requirements.

{mariadb-website}[{mariadb-long}] is a high-performance, open source relational database management system (RDBMS).
It began as a community-developed fork of MySQL to ensure the software remains free and accessible under the GPL license.
Native storage engines provide flexibility for diverse workloads.
Some highlights include:

* The InnoDB engine - ensures ACID compliance and transaction support.
* Aria - offers a crash-safe alternative to MyISAM.
* MEMORY - stores data in RAM for high-speed lookups.
* Spider - provides a partitioned, federated database solution.

Numerous database connectors also support the open source ecosystem.
This allows seamless integration with applications built in Python, Java, C++, and other languages.

{mariadb} supports database replication in a primary-replica topology, allowing organizations to see improved availability, minimized downtime, and increased performance.
And, {mep-long} is an option for business-critical environments, delivering even more enterprise features as well as enterprise-grade support.

{sles-website}[{sles-long}] provides a robust and reliable foundation for {mariadb} and {mep} deployments, making it a compelling choice for businesses that need enterprise-grade stability and support.
SUSE offers a 13-year lifecycle (10 years general support and 3 years extended support).
This gives organizations the confidence to run mission-critical applications without frequent, costly upgrades.

{sles} features broad hardware and cloud platform support.
It also provides access to a curated collection of securely packaged, maintained, and supported open source applications, including {mariadb} Server.
SUSE also delivers world-class support services, leveraging deep expertise in business-critical environments and a long history of working with demanding applications, such as SAP.
This ensures that customers receive responsive and expert assistance.

Together, SUSE and {mariadb} deliver open source innovation with enterprise reliability, performance, and scale.



=== Scope


This guide provides steps for deploying {mariadb-long} on {sles-long} in a basic primary-replica topology.

====
Although this guide was developed using {sles} {sles-version1} and {mariadb} {mariadb-version1} from the SUSE package repositories, you should have little difficulty leveraging this guidance for newer versions of these products.

* *Database Administrators (DBAs)*: DBAs are responsible for the database topology.
They would use the guide to implement {mariadb} replication for asynchronous or semi-synchronous primary-replica configurations to ensure that database services remain highly available.

== Architecture

image::SUSE-MariaDB-primary-replica.png[title="Basic Primary-Replica Topology", Basic Primary-Replica Topology, scaledwidth=90%]

To implement this architecture, you need at least two host systems.
One system will host the primary database instance and one will host the replica.
These can be physical machines, virtual machines, or cloud instances.

For the purposes of this guide, the following system specifications are adequate:

* Processor: 2 CPUs (or vCPUs)

* Memory: 4 GB of RAM

* Storage: 50 GB of disk storage

* Network: 1 Gbps Ethernet or better

You can find additional sizing guidance in the product documentation, and both SUSE and {mariadb} offer consulting and professional services that can help you design environments for enterprise scale.



== Preparing the hosts

Set up your primary and replica host systems as follows.

. Install {sles-long} on each host. +
Detailed installation guidance is available in the {sles-docs}[SUSE Linux Enterprise Server Documentation].

. Configure each host with an appropriate hostname and IP address. +
For example:
+
[cols="1,1,1",options="header"]
|===
|Hostname
|Role
|IP address

|host1
|Primary
|192.168.12.159

|host2
|Replica
|192.168.12.160
|===

. Register each host in order. +
This allows you to get product updates and technical support.

. Apply available patches and updates.

. Ensure port 3306 (MariaDB default port) and port 22 (SSH for file transfer) are open in the firewall (see https://documentation.suse.com/sles/16.0/html/firewalld).



== Installing {mariadb}

Perform the following steps on both primary and secondary hosts to install and secure MariaDB.

. Enable server module extension.
+
[source, console]
----
suseconnect -l sle-module-server-applications/16/886_64
----

. Install MariaDB.
+
[source, console]
----
sudo zypper install mariadb mariadb-client
----
+
[source, console]
----
sudo zypper install mariadb
----
+
[NOTE]
====
During installation, you may see messages stating that an empty database will be created at first start and that you should set a password for the MariaDB root user.
====

. Enable and start MariaDB.
+
[source, console]
----
systemctl enable --now mariadb
----
+
[source, console]
----
systemctl status mariadb
----

. Secure MariaDB with a good root user password by using one of the following options.
+
* Set the password with the command:
+
[source, console]
----
/usr/bin/mariadb-admin -u root password 'my-secure-PASS-123'
----
+
Be sure to replace 'my-secure-PASS-123' with your own secure password.

* Alternatively, execute use the secure installation script:
+
[source, console]
----
/usr/bin/mariadb-secure-installation
----
+
This interactive script provides prompts you to select security configuration options, including:
+
--
* seting a password for the MariaDB root accounts
* removing MariaDB root accounts that are accessible outside the local host
* removing anonymous user accounts
* removing the test database
--
+
[NOTE]
====
The `mariadb-secure-installation` script is also symlinked as `mysql-secure-installation` to maintain compatibility.
====


== Configuring the primary database

Log into the primary server and perform the steps below.


. Edit the global MariaDB configuration file, `/etc/my.cnf.d/server.cnf`, with the following options:
+
[listing]
----
[mysqld]
server-id=1
log_bin=mysql-bin
binlog_format=ROW
binlog_row_image=FULL
sync_binlog=1
innodb_flush_log_at_trx_commit=1
bind-address=0.0.0.0
----

. Restart the MariaDB service for the changes to take effect.
+
[source, console]
----
sudo systemctl restart mariadb
----

. Grant access to the 'replica' user.

.. Log into the MariaDB server.
+
[source, console]
----
mariadb -u root -p
----
+
Provide your secure, root password when prompted.

.. At the MariaDB command prompt (`MariaDB [(none)]>`), enter:
+
[source, console]
----
GRANT replication slave ON *.* to replica@'%' IDENTIFIED BY 'my-replica-password';
----

.. Flush privileges for this change to take effect.
+
[source, console]
----
flush privileges;
----

.. Log out of the MariaDB server.
+
[source, console]
----
quit
----
